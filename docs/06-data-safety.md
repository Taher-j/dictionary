# Data safety: snapshots, backup, restore, import, export

All data lives in one SQLite file in the app's documents directory. The app contains no network
code. Three layers protect the data; none needs a server.

| Layer | Protects against | Stage |
| --- | --- | --- |
| Automatic local snapshots | A bad import, a faulty migration, an accidental mass delete | M5 (snapshot-before-migrate already in M1) |
| Manual full backup (JSON) | A lost, broken or replaced phone | M5 |
| OS device backup | A lost phone, if the user has device backup enabled | Free bonus; verify on a real device, do not rely on it |

## Snapshots

- Copy the database file into `snapshots/` (inside app storage) after a WAL checkpoint.
- When: first launch of each study day; before every migration, import and restore.
- Keep the newest five; delete older ones.
- Settings lists snapshots with date and size and can restore one (after confirming).

## Backup file

One JSON file, written table by table in chunks (never build one giant string in memory).
File name: `dictionary-backup-YYYY-MM-DD.json`.

```json
{
  "format": "dictionary-backup",
  "formatVersion": 1,
  "schemaVersion": 1,
  "exportedAt": "2026-10-05T18:30:00Z",
  "app": { "version": "1.0.0", "platform": "android" },
  "data": {
    "dictionaries": [],
    "words": [],
    "tags": [],
    "wordTags": [],
    "cards": [],
    "reviewLogs": [],
    "sessions": [],
    "settings": []
  }
}
```

- Includes soft-deleted rows (tombstones) so merge works later.
- Does not include `import_batches` history or snapshots.
- "Back up now" writes the file to the cache directory and opens the system share sheet.
- Record `lastBackupAt` in `settings`.
- The backup screen states plainly that the file is not encrypted.

## Restore

1. Pick a file. Validate `format`; reject unknown formats with a clear message.
2. Upgrade older `formatVersion` files through chained pure functions in
   `src/domain/backup/upgrade.ts` (`v1 -> v2 -> ...`).
3. Show a preview: dictionaries, words, reviews, export date.
4. **Replace** (M5): take a snapshot, then delete all rows and insert the backup inside one transaction.
5. **Merge** (M6): match rows by `id`. The row with the later `updated_at` wins. Tombstones are
   honoured. Review logs are unioned by `id`.

Restore matches by id, never by term, so it involves no duplicate detection. Merging the same file
twice changes nothing.

## Backup reminder

Show a banner on Today when both are true: 14 or more days since `lastBackupAt` (or never), and
20 or more words created or edited since then.

## Migrations

- Generated by drizzle-kit, bundled with the app, run at startup inside a transaction.
- A snapshot is taken before any pending migration runs.
- A committed migration is never edited. Fixes go in a new migration.
- Tests: migrate from empty; migrate a fixture database of each released schema version to latest.

## Import (Milestone 6)

Pipeline; only the last step touches the database:

1. **Parse** — SheetJS (XLSX) or Papa Parse (CSV/TSV) -> rows of strings. Detect delimiter
   (comma, semicolon, tab) and strip a UTF-8 BOM.
2. **Map** — column mapping (auto-guessed from header names, user-adjustable) -> candidate words.
3. **Validate** — drop empty rows, trim, split tags on `,` and `;`, flag rows without a term,
   cap cell length.
4. **Plan** — compare with existing `term_norm` / `term_fold` keys (loaded once into maps) and
   produce insert / update / skip actions per row. Rows repeated inside the file collapse to the
   first occurrence.
5. **Apply** — take a snapshot, create an `import_batches` row, execute the plan in transactions of
   about 500 rows, report progress.

- The preview screen renders the plan from step 4; step 5 does exactly that.
- Limits: 10 MB file size, 50,000 rows. Larger files get a clear message.
- Read cached cell values. Never evaluate formulas.
- Any parse failure produces a message, never a crash.
- "Undo import" soft-deletes every word with that `import_batch_id`.
- Imported complete words get a `recognition` card like any other word; the daily new-word limit
  paces them.

## Export (Milestone 6)

- Scopes: one dictionary, the current selection/filter, or everything.
- Formats: XLSX and CSV. CSV is written with a UTF-8 BOM so Excel reads accents correctly.
- Columns: Dictionary, Term, Translation, Definition, Example, Part of speech, Forms,
  Pronunciation, Notes, Source, Tags (comma-separated), Starred, Created.
- Prefix any cell starting with `=`, `+`, `-` or `@` with an apostrophe (formula injection).
- The export screen states that spreadsheets carry no review history; use Backup for that.

## Security and privacy rules

- No network requests anywhere. No `expo-updates`, analytics, crash reporting or ads.
- No database encryption (the OS sandbox and storage encryption cover it).
- `/add` deep links and shared text only prefill the quick-add sheet. Nothing is saved without a tap.
  Cap `term` at 200 characters and `context` at 2,000.
- Lookup links (V1) open the system browser and are the only outbound path; always user-initiated.
- Privacy wording for the app and store listing: "Your words stay on your device and in backups
  you control."
